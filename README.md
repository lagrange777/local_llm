# Local LLM Service

Веб-чат на Go с локальной моделью Ollama + Qwen3. Приложение работает без облачной генерации; сервер и модель упакованы в Docker.

Модель проекта по умолчанию — **`qwen3:8b`**. Режимы `think=false` и `think=true` проверены на реальном локальном API: [результаты сравнения](artifacts/think-modes/REPORT.md).

## Локальный RAG — задание 28

Готовые чанки SQLite-индекса соседнего проекта импортированы с исходными метаданными. Веб-чат поддерживает локальный BM25, ответы Qwen с источниками и точными цитатами, отказ при слабом контексте и режим без RAG. Поиск и генерация работают без облачных API. [Пайплайн, запуск, контрольные вопросы и сравнение](RAG28.md).

```sh
docker compose up -d --build
python3 scripts/evaluate-rag.py --output artifacts/rag28-new
```

Чат: http://127.0.0.1:8081; сравнение: http://127.0.0.1:8081/comparison. Соседний проект нужен только при повторном импорте индекса.

## Веб-чат в Docker — задание 27

```sh
docker compose up -d --build
```

Откройте **http://127.0.0.1:8081**. Нужен Docker Compose v2 или новее, свободное место для весов (примерно 5,2 GB) и достаточная память Docker (проверено с 8 GiB). Первый запуск скачивает образы и модель; последующие используют том `local-llm_models`.

Если веса уже загружены для задания 26, перед первым запуском можно импортировать только нужную модель и избежать повторного скачивания:

```sh
python3 scripts/import-model.py --source data/models --model qwen3:8b
docker compose up -d --build
```

Не импортируйте веса поверх работающей модели. Для другого каталога укажите путь в `--source`; импорт поддерживает имена моделей Ollama library с явным тегом.

Интерфейс показывает ответ по мере генерации, сохраняет историю в этом браузере и передаёт её в следующие вопросы. Есть «Новый диалог», «Остановить» и переключатель рассуждений (по умолчанию выключен). Рассуждения показываются отдельно. Остановленные и ошибочные ответы не включаются в контекст.

При недоступной Ollama, отсутствующей модели или превышении тайм-аута приложение показывает ошибку. Один запрос генерируется за раз; другие получают сообщение о занятости модели. В контекст входят до 10 завершённых обменов и текущий вопрос; ранние пары удаляются при превышении бюджета 6000 символов. Текущий вопрос ограничен 4000 символами. Это простой бюджет по символам, а не точный подсчёт токенов. Для RAG действует отдельный бюджет контекста; подробности в RAG28.md.

Генерация не использует облачные модели: `OLLAMA_NO_CLOUD=1`, приложение не содержит клиента облачного провайдера. Go-приложение и Ollama подключены только к Docker-сети `runtime` с `internal:true`. Входной Nginx принимает запросы на loopback-порту и передаёт их приложению. Отдельный `model-init` имеет доступ к интернету только для подготовки модели, затем завершается. [Подробности Docker](deploy/README.md).

На Apple Silicon Ollama внутри Linux-контейнера использует CPU; ответы могут быть медленнее, чем у нативной Ollama с Metal. Для Linux с NVIDIA и установленным NVIDIA Container Toolkit есть конфигурация:

```sh
docker compose -f compose.yaml -f compose.gpu.yaml up -d --build
```

GPU-вариант здесь не запускался. По умолчанию работает переносимая CPU-конфигурация.

Настройки Compose: `OLLAMA_MODEL` (qwen3:8b), `WEB_PORT` (8081), `CHAT_TIMEOUT` (5m). Скопируйте `.env.example` в `.env` при необходимости. Ollama API наружу не публикуется.

```sh
docker compose ps -a
docker compose logs -f app ollama
docker compose restart app ollama gateway
docker compose down
```

`down` сохраняет веса. `down -v` удалит том и потребует повторной подготовки модели.

## API приложения

```sh
curl -N http://127.0.0.1:8081/api/chat \\
  -H 'Content-Type: application/json' \\
  -d '{"messages":[{"role":"user","content":"Сколько будет 17 * 23? Ответь только числом."}],"think":false}'
```

Ответ — NDJSON: события `start`, `delta`, `thinking`, `done` либо `error`. История передаётся как последовательность `user/assistant`, заканчивающаяся новым `user`. Модель и системная инструкция задаются сервером. `GET /api/status` проверяет наличие модели; `GET /healthz` — работоспособность приложения.

Для проверки реальной интеграции:

```sh
python3 scripts/verify-web.py
```

Прогон выполняет факт, расчёт, уточнение с историей, генерацию Go-функции и запрос с рассуждениями. Сохраняет исходные события, ответы и метрики в `artifacts/web-run/`; проверяет шесть случаев сгенерированной функции. [Отчёт задания 27](artifacts/web-run/REPORT.md).

## Запуск веб-чата без Docker

При запущенной нативной Ollama:

```sh
go run ./cmd/server
```

Адрес по умолчанию — `127.0.0.1:8081`, Ollama — `http://127.0.0.1:11434`. Переменные `WEB_ADDR`, `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `CHAT_TIMEOUT` нужно экспортировать в оболочку. Не запускайте нативный сервер и Docker-вариант на одном порту.

## Установка нативной Ollama на macOS

Нужны Homebrew, Python 3 и Go 1.25 или новее.

```sh
brew install ollama
python3 scripts/start-ollama.py
ollama pull qwen3:8b
```

Скрипт запускает фоновый процесс на `127.0.0.1:11434` с `OLLAMA_NO_CLOUD=1`. Веса хранятся в `data/models/`, журнал и PID — в `tmp/`; эти каталоги исключены из Git. Если порт уже занят Ollama, скрипт сообщает об этом и не меняет настройки существующего процесса. После перезагрузки компьютера скрипт запускают снова.

Установка пакета и загрузка весов используют интернет. Генерация выполняется на Mac через локальный HTTP API. Загруженная модель 8B занимает около 5,2 GB на диске; проверка выполнялась на Apple M1 Pro с 16 GiB RAM.

## Запрос через HTTP

Без рассуждений:

```sh
curl --fail-with-body --max-time 180 http://127.0.0.1:11434/api/generate \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3:8b","prompt":"Сколько будет 17 * 23? Ответь только числом.","stream":false,"think":false,"options":{"temperature":0,"num_ctx":4096,"num_predict":2048}}'
```

Для режима с рассуждениями измените `think` на `true`. Итоговый ответ приходит в `response`, рассуждения — отдельно в `thinking`. При `false` поле `thinking` отсутствует или пустое. `stream:false` возвращает один JSON после завершения генерации; режим с рассуждениями может занять десятки секунд.

Параметр `think` передаётся на верхнем уровне JSON, вне `options`. Go-клиент отправляет явное значение в обоих режимах и сохраняет отдельное поле `thinking`.

## Запрос через CLI

```sh
ollama run qwen3:8b --think=false --verbose "Сколько будет 2 + 2? Ответь только числом."
ollama run qwen3:8b --think=true --verbose "Сколько будет 2 + 2? Ответь только числом."
```

## Проверка обоих режимов

```sh
go run ./cmd/verify-think
```

Программа задаёт три вопроса в двух режимах: факт (столица Франции), вычисление (17 × 23) и объяснение RAG. Сохраняет запросы, ответы, поле `thinking`, время, число токенов и результаты проверок в `artifacts/think-modes/`. Параметры одинаковы: `temperature=0`, `seed=42`, контекст 4096, максимум 2048 выходных токенов, тайм-аут 3 минуты.

Проверяются завершённость ответа, ожидаемый результат арифметики и факта, ключевые понятия объяснения RAG, наличие рассуждений только при `true` и отсутствие тегов рассуждения в итоговом ответе. Проверка ключевых слов — ограниченная эвристика; сами ответы также приведены в отчёте. Ошибка API или проверки приводит к ненулевому коду завершения.

Повторный запуск обновляет файлы. Для отдельного прогона:

```sh
go run ./cmd/verify-think -output artifacts/another-comparison
```

## Три запроса разной сложности

```sh
go run ./cmd/verify -think=false
go run ./cmd/verify -think=true -output artifacts/verification-thinking
```

Программа проверяет простой факт, расчёт скидки и генерацию Go-функции. По умолчанию рассуждения отключены, результаты сохраняются в `artifacts/verification/`. Ожидания предназначены для ручной оценки смысла; автоматически проверяются успешность API и полнота ответа.

Адрес и модель задаются флагами `-url`, `-model` или переменными `OLLAMA_BASE_URL`, `OLLAMA_MODEL`. Настройки `.env.example` нужно экспортировать в оболочку: файл не загружается автоматически.

## Почему модель по умолчанию изменилась

У установленной `qwen3:4b` с Ollama 0.40.3 значение `think=false` не отключало генерацию рассуждений: на вопрос 2 + 2 оба режима выдавали 264 токена, а при `false` рассуждения попадали в `response` вместе с `</think>`. Изменения шаблона не исправили поведение на всех проверочных вопросах.

Поэтому проект использует отдельно загруженную `qwen3:8b`, у которой переключение работает в проверенных запросах. Старые веса 4B не переименованы и не заменены. В прямых запросах к Ollama нужно явно указывать `"model":"qwen3:8b"`; запрос с `qwen3:4b` продолжит использовать старую модель.

[Первоначальный отчёт с 4B](artifacts/local-run/REPORT.md) сохранён как история выполнения задания. [Новый отчёт](artifacts/think-modes/REPORT.md) содержит оба режима 8B и исходную диагностику 4B.

## Структура

```text
cmd/server/        сервер веб-чата
internal/web/      API и встроенный интерфейс
cmd/verify/        три контрольных запроса
cmd/verify-think/  сравнение двух режимов на трёх вопросах
internal/ollama/   HTTP-клиент и тесты
scripts/          запуск локального процесса
deploy/           место для будущего облачного развёртывания
artifacts/        реальные результаты и отчёты
data/models/      веса (исключены из Git)
tmp/              журнал и PID (исключены из Git)
```
