# Docker и развёртывание

Основной запуск: `docker compose up -d --build`. UI доступен на http://127.0.0.1:8081.

## Компоненты

- `model-init`: запускает временную Ollama, проверяет наличие выбранной модели, при необходимости скачивает веса и завершается. Использует сеть bootstrap с доступом к интернету.
- `ollama`: выполняет модель, `OLLAMA_NO_CLOUD=1`, веса в постоянном томе models; наружу порт не публикуется.
- `app`: Go-сервер, встроенный интерфейс, потоковый API и отмена запросов. Образ собирается с тестами; выполняется без root и с файловой системой только для чтения.
- `gateway`: Nginx, публикует только loopback-порт 8081 и проксирует поток без буферизации. Подключён к ingress и runtime.

App и Ollama подключены только к сети runtime с `internal:true`. У них нет внешнего маршрута. Gateway обеспечивает доступ из браузера. Образы Ollama и Nginx зафиксированы дайджестами.

Первый запуск требует интернет для получения образов и весов; генерация после подготовки работает в закрытой сети. Том весов сохраняется при остановке контейнеров.

## Проверка

```sh
docker compose ps -a
curl --fail http://127.0.0.1:8081/api/status
docker network inspect local-llm_runtime --format '{{.Internal}}'
docker inspect local-llm-app-1 --format '{{json .NetworkSettings.Networks}}'
docker inspect local-llm-ollama-1 --format '{{json .NetworkSettings.Networks}}'
python3 scripts/verify-web.py
```

## Ресурсы и облако

CPU-вариант проверен на Docker Desktop / Apple M1 Pro с примерно 8 GiB RAM у Docker. Веса qwen3:8b занимают около 5,2 GB. Linux-контейнер на Mac не использует Metal; скорость отличается от нативного запуска.

На Linux/NVIDIA подготовьте NVIDIA Container Toolkit и примените `compose.gpu.yaml`. Этот вариант не проверен на текущем Mac.

Для облачного публичного сервиса следующим этапом нужны выбранный CPU/GPU-хост, домен/TLS, авторизация и ограничения нагрузки. Текущая конфигурация публикует только loopback-порт и предназначена для локального использования. Облачная машина выполняет те же веса самостоятельно, без API облачной модели.

## Локальный RAG

`documents/chunks.json` включён в образ приложения. Это экспорт существующего SQLite-индекса: BM25 строится локально при старте, embedding-модель и интернет не нужны. Для обновления корпуса выполните `python3 scripts/import-rag.py`, затем пересоберите app. Индекс не содержит API-ключей или облачного клиента. Результаты контрольного прогона подключены в `/reports` только для чтения. Настройки поиска и сравнение описаны в [RAG28.md](../RAG28.md).

## Оптимизация модели

Профиль по умолчанию задаётся RAG_PROFILE. Основное приложение включает индекс и оба prompt; результаты подключены в /optimization-reports только для чтения. model-init готовит модель выбранного профиля. Для полного эксперимента подготовьте все модели через compose.optimization.yaml; подробности в [OPTIMIZATION29.md](../OPTIMIZATION29.md). Кэш промптов ограничен 512 МиБ, даже при переключении моделей. Память контейнера и память Docker VM измеряются отдельно: уменьшение веса модели не уменьшает автоматически резерв всей VM.
