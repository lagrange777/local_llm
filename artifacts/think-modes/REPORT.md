# Проверка переключения think

Проверено 11 октября 2026 года на локальном Ollama 0.40.3, Apple M1 Pro, 16 GiB RAM. Модель проекта: **qwen3:8b**, Q4_K_M. Используется локальный HTTP API на 127.0.0.1:11434; облачная генерация отключена.

## Изменение

Модель по умолчанию в Go-командах и .env.example заменена на qwen3:8b. В cmd/verify добавлен флаг -think (по умолчанию false). Клиент сохраняет response и thinking раздельно и явно отправляет булево значение think, включая false. Добавлен cmd/verify-think для сравнения одинаковых вопросов в двух режимах.

Веса старой qwen3:4b сохранены под исходным именем. Чтобы получить исправленное поведение через прямой API или CLI, нужно выбрать qwen3:8b. Сервер Ollama и веса 4B не модифицированы.

## Исходная проблема с 4B

На вопрос «Сколько будет 2 + 2? Ответь только числом.» оба режима исходной 4B генерировали 264 токена: false — 6,36 с, true — 6,15 с. При false ответ содержал рассуждения и закрывающий тег </think>, хотя отдельное поле thinking было пустым. Таким образом, отсутствие поля thinking само по себе не означало отключение рассуждений.

Пробовали условный шаблон и префикс закрытого блока thinking; на контрольных вопросах 4B продолжала выдавать рассуждения. Для рабочего решения использована отдельно загруженная 8B со штатным шаблоном. [Исходные запросы и ответы 4B](before-4b.json) сохранены.

## HTTP: одинаковые вопросы в двух режимах

Команда: `go run ./cmd/verify-think -model qwen3:8b`.

Параметры обоих режимов: temperature=0, seed=42, num_ctx=4096, num_predict=2048, stream=false. Шесть запросов выполнены последовательно. Таблица показывает фактическую длительность отдельного прогона, а не результат нагрузочного тестирования. Число выходных токенов при true включает рассуждения и итоговый ответ.

| Question | think | Time (s) | Output tokens | Thinking characters | Result |
|---|---|---:|---:|---:|---|
| fact | false | 0.55 | 4 | 0 | passed |
| fact | true | 6.79 | 156 | 414 | passed |
| math | false | 0.40 | 4 | 0 | passed |
| math | true | 33.81 | 776 | 2168 | passed |
| explanation | false | 3.09 | 71 | 0 | passed |
| explanation | true | 10.49 | 243 | 522 | passed |

Все 6 проверок прошли: правильный ответ на факт и арифметику, завершённая генерация, отсутствие тегов thinking в response, непустое thinking только при true. При false проверенные ответы не содержат рассуждений, и число выходных токенов существенно меньше. Для объяснения RAG дополнительно проверены ключевые понятия и отсутствие нескольких маркеров самокомментирования; смысл обоих ответов проверен по сохранённому тексту. Эта эвристика не гарантирует отсутствие самокомментирования на любых возможных вопросах.

### Ответы на объяснение RAG

**think=false**

RAG — это подход, при котором система ищет информацию в внешних источниках и использует её для генерации точного и актуального ответа на запрос. Он позволяет модели отвечать на вопросы, основываясь на данных из надежных источников, а не только на предобученных данных.

**think=true**

RAG (Retrieval-Augmented Generation) — это подход, при котором модель сначала ищет информацию в внешних источниках, а затем генерирует ответ на основе найденных данных, чтобы обеспечить точность и актуальность. Система комбинирует поиск и генерацию, чтобы предоставлять более надежные и информативные ответы.

## Воспроизведение

```sh
python3 scripts/start-ollama.py
ollama pull qwen3:8b
go run ./cmd/verify-think -output artifacts/recheck
go test ./...
go vet ./...
```

API:

```json
{
  "model": "qwen3:8b",
  "prompt": "Сколько будет 17 * 23? Ответь только числом.",
  "stream": false,
  "think": false,
  "options": {
    "temperature": 0,
    "num_ctx": 4096,
    "num_predict": 2048
  }
}
```

Для второго режима укажите think=true. Ответ читается из response, рассуждения — из thinking. В режиме true API может отвечать десятки секунд; не используйте короткий тайм-аут.
